4. Mapa de navegación 
 

 
 
1. Flujo de Onboarding (Lineal y Secuencial) 
• Paso 1: El usuario ingresa a la Pantalla de Registro para crear su cuenta. 
• Paso 2: Tras registrarse, es redirigido automáticamente a la pantalla de 
Selección de Intereses.  
• Propósito: Garantizar que el usuario configure sus juegos y equipos favoritos 
antes de ingresar a la app para poder personalizar el contenido inicial.  
2. Navegación Principal (Horizontal / Menú de Pestañas) 
Una vez completado el registro, el usuario accede a la vista principal. Las 3 pantallas 
clave (Feed de Intereses, Matchmaking y Calendario de Scrims) están 
interconectadas en un mismo nivel:  
• Feed de Intereses: Funciona como la pantalla de inicio (Home), mostrando 
noticias y resultados personalizados.  
• Matchmaking: Permite aplicar filtros para buscar y contactar jugadores.  
• Calendario de Scrims: Permite consultar y agendar partidas con el equipo.  
Mecanismo de transición: 
El cambio entre estas tres pantallas se gestiona mediante una Barra de Navegación 
Inferior (Bottom Navigation Bar). Esto permite al usuario cambiar de sección de 

manera rápida y directa en cualquier momento, manteniendo activa la sesión y 
preservando el estado de cada pantalla al alternar entre ellas. 
5. Datos locales y remotos 
Datos locales 
Se almacenarán localmente: 
• Sesión del usuario. 
• Token de autenticación. 
• Preferencias básicas del usuario. 
• Últimos contenidos consultados. 
• Caché de noticias. 
• Configuraciones de la aplicación. 
Justificación: 
Estos datos pueden mantenerse temporalmente en el dispositivo para reducir tiempos 
de carga y permitir que cierta información siga disponible cuando exista una conexión 
inestable. 
La idea original también contempla el uso de caché y paginación para manejar el feed 
dinámico. 
Datos remotos 
Se almacenarán en el servidor/base de datos: 
• Usuarios. 
• Perfiles de jugadores. 
• Juegos. 
• Equipos. 
• Integrantes de equipos. 
• Partidas programadas. 
• Preferencias de intereses. 
• Noticias y resultados. 
• Información obtenida de APIs externas. 
Justificación: 

Estos datos necesitan mantenerse sincronizados entre diferentes dispositivos y 
usuarios. Además, la aplicación requiere consumir APIs externas de diferentes juegos, 
como Riot API y Steam API.
