# Actividad Semana 02 — Backlog ágil de CORHUILA Plus

**Asignatura:** Programación Móvil
**Semana:** 2
**Aplicación:** CORHUILA Plus

## 1. Historias de usuario

### HU-01 — Ingreso a la aplicación

**Como estudiante, quiero ingresar a CORHUILA Plus con mis datos de acceso para utilizar las funcionalidades académicas disponibles en la aplicación.**

**Criterios de aceptación:**

1. El sistema debe permitir el ingreso cuando el estudiante proporcione los datos requeridos correctamente.
2. Al ingresar correctamente, el sistema debe mostrar la pantalla principal de la aplicación.

**Prioridad:** Imprescindible
**Sprint:** 1

---

### HU-02 — Visualización del panel principal

**Como estudiante, quiero visualizar un panel principal después de ingresar para acceder fácilmente a las opciones disponibles en CORHUILA Plus.**

**Criterios de aceptación:**

1. Después de iniciar sesión, el estudiante debe visualizar el panel principal.
2. Desde el panel principal, el estudiante debe poder acceder a las opciones habilitadas de la aplicación.

**Prioridad:** Imprescindible
**Sprint:** 1

---

### HU-03 — Navegación por las opciones de la aplicación

**Como estudiante, quiero utilizar el menú de navegación para desplazarme entre las diferentes opciones de CORHUILA Plus de manera sencilla.**

**Criterios de aceptación:**

1. El menú debe permitir al estudiante seleccionar las opciones disponibles.
2. Al seleccionar una opción, la aplicación debe mostrar la pantalla correspondiente sin necesidad de cerrar la sesión.

**Prioridad:** Imprescindible
**Sprint:** 2

---

### HU-04 — Realización del proceso de matrícula

**Como estudiante, quiero realizar mi proceso de matrícula desde la aplicación para completar este procedimiento de manera organizada.**

**Criterios de aceptación:**

1. La aplicación debe permitir al estudiante avanzar por las etapas definidas del proceso de matrícula.
2. El sistema debe permitir finalizar el proceso cuando se hayan completado los datos o pasos requeridos.

**Prioridad:** Imprescindible
**Sprint:** 2

---

### HU-05 — Generación del horario académico

**Como estudiante, quiero generar mi horario académico después de completar el proceso de matrícula para conocer la distribución de mis actividades académicas.**

**Criterios de aceptación:**

1. La opción de generar horario debe estar disponible cuando el estudiante haya completado el proceso necesario para ello.
2. Al seleccionar la opción de generar horario, la aplicación debe mostrar el horario correspondiente en pantalla.

**Prioridad:** Imprescindible
**Sprint:** 3

---

### HU-06 — Consulta del horario generado

**Como estudiante, quiero consultar mi horario académico desde la aplicación para revisar posteriormente la información generada.**

**Criterios de aceptación:**

1. Después de generar el horario, el estudiante debe poder visualizarlo desde la aplicación.
2. La información del horario debe presentarse de manera organizada para facilitar su consulta.

**Prioridad:** Deseable
**Sprint:** 3

---

# 3. Organización por sprints

## Sprint 1 — Acceso y pantalla principal

**Objetivo:** permitir que el estudiante ingrese a CORHUILA Plus y tenga acceso a la interfaz principal de la aplicación.

* HU-01 — Ingreso a la aplicación.
* HU-02 — Visualización del panel principal.

## Sprint 2 — Navegación y matrícula

**Objetivo:** permitir que el estudiante se desplace por la aplicación y complete el proceso de matrícula.

* HU-03 — Navegación por las opciones de la aplicación.
* HU-04 — Realización del proceso de matrícula.

## Sprint 3 — Horario académico

**Objetivo:** permitir que el estudiante genere y consulte su horario académico.

* HU-05 — Generación del horario académico.
* HU-06 — Consulta del horario generado.

# 4. Resultado del backlog

El backlog de CORHUILA Plus se organizó dando prioridad a las funciones necesarias para que el estudiante pueda utilizar la aplicación de forma progresiva. Primero se desarrolla el acceso y el panel principal; posteriormente, la navegación y el proceso de matrícula; y finalmente, la generación y consulta del horario académico.

De esta manera, las historias de usuario se encuentran organizadas en tres sprints y cada una incluye criterios de aceptación que permiten comprobar su cumplimiento.
